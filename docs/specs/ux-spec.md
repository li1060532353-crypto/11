## 1. 规范定位与核心设计原则

### 1.1 规范背景与定位
本规范基于 `codex-master-spec.md` 及 `gemini-multi-agent-execution-plan-2026-10-01.md` 编制，旨在彻底解决现有系统在“阅读返回链路破损”、“后台管理功能欠缺与中英文混杂”、“编辑工作台表单遮挡正文”、“版本恢复缺乏安全熔断”以及“多端响应式体验割裂”等关键交互缺陷。

本规范作为 **Wave 1** 的交互设计交付物，为后续 Wave 2 (N, M)、Wave 3 (E) 的组件与页面实现提供绝对权威的视觉流转、状态判定、异常容错与键盘无障碍标准。

### 1.2 核心交互设计原则

1. **闭环可逆 (Closed-Loop & Deterministic Navigation)**
   - 任何进入文章阅读或预览的路径，都必须保持确定、可感知的返回通路。无论经过多少次相邻文章连续翻页，必须能够一键或精准按原路径返回最初的发现列表（保持原有页码、筛选条件、搜索词及滚动偏移）。
2. **正文优先 (Content-First Workbench)**
   - 编辑器必须确立以创作正文为绝对视觉重心的架构。移除标题与画布之间堆叠的臃肿元数据表单；属性设置沉降至右侧折叠面板（移动端为抽屉），提供沉浸、无干扰的技术写作体验。
3. **数据安全熔断 (Safety Circuit Breaker)**
   - 绝不信任未经验证的异步操作。未保存草稿有强离开拦截；恢复历史版本前，必须强制完成当前工作区的自动持久化与安全快照备份，任何前置步骤失败必须坚决中止覆盖。
4. **状态真实与直观反馈 (Transparent State Machine)**
   - 杜绝将后端故障、网络中断或权限不足掩盖为“暂无数据”或假空列表。清晰暴露 `loading`、`ready`、`empty`、`error`、`saving`、`saved`、`failed` 等原子状态。
5. **严密中文化与私有语义一致 (Consistent Terminology)**
   - 系统全站属于单所有者私有知识库。全面清除未翻译英文（如 Overview, Articles, Settings 假入口）；严格禁止在私有模式下使用“公开文章”等具有外部泄漏歧义的文案，统一使用“阅读视图”或“正式阅读”。
6. **响应式与包容性 (Inclusive & Multi-Device Accessibility)**
   - 完整适配 1440px 桌面大屏、1024px 平板/笔记本、390px 移动手机以及 320px 极端小屏。严格保证无水平溢出，全量支持键盘 Tab 导航、焦点陷阱与无障碍阅读标准。

## 2. 阅读区“查找文章 → 阅读 → 返回”闭环规范

### 2.1 来源识别与链路追踪协议 (`NavigationSourceState`)

为了使读者在阅读文章后能够精准返回进入点（如搜索结果第 2 页第 5 项），系统统一通过 React Router 的 `location.state` 以及标准化导航载荷进行状态流转。

#### 2.1.1 状态数据结构规范

```typescript
export type NavigationRootType =
  | 'post_list'       // 前台全部文章列表 (/posts)
  | 'search_list'     // 搜索结果列表 (/search)
  | 'taxonomy_list'   // 分类/标签/归档列表 (/categories/:slug, /tags/:slug, /archives)
  | 'admin_notes'     // 后台文章管理列表 (/knowledge/notes)
  | 'admin_editor'    // 编辑工作台预览 (/knowledge/notes/:id)
  | 'direct';         // 直接打开/新标签/外链访问

export interface RootSourceState {
  type: NavigationRootType;
  /** 返回按钮展示文案 */
  label: string;
  /** 目标路由路径 (含 pathname) */
  path: string;
  /** 完整的 search 查询串，如 "?q=react&page=2" */
  search: string;
  /** 离开列表时的垂直滚动像素位置 */
  scrollY: number;
  /** 关键筛选元数据快照 */
  meta?: {
    page?: number;
    query?: string;
    category?: string;
    tag?: string;
    tab?: string;
    noteId?: string;
  };
}

export interface ArticleLocationState {
  /** 根来源定义 */
  rootSource?: RootSourceState;
  /** 连续翻页跳数 (初始进入为 0，每点击一次上一篇/下一篇 +1) */
  hopCount?: number;
}
```

#### 2.1.2 典型进入场景的协议构造规则

| 触发入口 | 来源类型 `type` | 格式化回退文案 `label` | 携带元数据 `meta` | 兜底行为 |
| :--- | :--- | :--- | :--- | :--- |
| **全部文章列表** (`/posts?page=2`) | `post_list` | `← 返回文章列表 (第 2 页)`<br>*(第 1 页则为 `← 返回文章列表`)* | `{ page: 2 }` | `/posts` |
| **搜索结果列表** (`/search?q=rust&page=1`) | `search_list` | `← 返回搜索结果 "rust"` | `{ query: 'rust', page: 1 }` | `/search?q=rust` |
| **分类列表** (`/categories/engineering`) | `taxonomy_list` | `← 返回分类 [工程实践]` | `{ category: '工程实践' }` | `/categories` |
| **标签列表** (`/tags/react`) | `taxonomy_list` | `← 返回标签 #react` | `{ tag: 'react' }` | `/tags` |
| **后台文章管理** (`/knowledge/notes?tab=draft&page=3`) | `admin_notes` | `← 返回文章管理 (草稿 · 第 3 页)` | `{ tab: 'draft', page: 3 }` | `/knowledge/notes` |
| **编辑工作台预览** (`/knowledge/notes/:id`) | `admin_editor` | `← 返回正在编辑的文章` | `{ noteId: 'uuid' }` | `/knowledge/notes/:id` |
| **直接访问 / 新标签打开** | `direct` | `← 返回文章列表` (前台)<br>`← 返回文章管理` (后台) | 无 | 前台 `/posts`<br>后台 `/knowledge/notes` |

### 2.2 顶部与底部返回入口规范

#### 2.2.1 顶部快捷返回控制条 (Top Breadcrumb / Return Toolbar)
- **展示位置**：
  - 前台阅读页 (`PostDetailPage.tsx`)：位于文章 Header 顶部，紧随网站主导航下方。
  - 知识库阅读页 (`KnowledgeNoteReadRoute.tsx`)：位于操作条左侧 (`knowledge-reader-toolbar__left`)。
- **文案逻辑**：
  - 当读取到有效的 `location.state.rootSource` 时，严格展示对应的 `rootSource.label`。
  - 当为 `direct` 模式（无 state）时，自动降级为安全默认项：`← 返回文章列表`。**严禁直接调用 `history.back()`，避免导致用户跳转到搜索引擎、空白页或站外站点。**
- **点击行为**：
  - 使用 `<Link to={`${rootSource.path}${rootSource.search}`} state={{ restoreScroll: true, scrollY: rootSource.scrollY }}>` 进行定向跳回。

#### 2.2.2 底部相邻文章翻页与根来源透传机制 (NAV-02)
- **相邻文章翻页问题**：
  - 读者从搜索“typescript”进入第 1 篇文章，连续点击“下一篇”阅读了 4 篇相关文章。若返回直接取上一个 history，用户需要连续按 4 次后退，极易在文章间产生闭环死循环。
- **状态流转机制**：
  - 当用户在文章底部点击【上一篇】或【下一篇】时，生成新链接的跳转参数中，**必须完整继承当前的 `rootSource`**，并将 `hopCount = (hopCount || 0) + 1`。
  ```tsx
  <Link
    to={`/posts/${nextPost.slug}`}
    state={{
      rootSource: location.state?.rootSource ?? defaultDirectSource,
      hopCount: (location.state?.hopCount ?? 0) + 1,
    }}
  >
    <span>下一篇</span>
    {nextPost.title}
  </Link>
  ```
- **底部增加“根来源跳回”通道**：
  - 若 `hopCount > 0`，在“上一篇 / 下一篇”导航栏下方，追加居中轻量操作：
    - 文案：“已在文章间连续阅读 N 篇 · [直接返回最初来源: {rootSource.label}]”
    - 点击后一键回到起点列表，彻底打破线性浏览的返回阻碍。

### 2.3 滚动行为与位置恢复规范 (NAV-01)

#### 2.3.1 推进与返回判定矩阵

| 场景分类 | 路由动作 | 判定条件 | 滚动策略 | 预期行为 |
| :--- | :--- | :--- | :--- | :--- |
| **推进新文章** | PUSH | 访问全新文章 Slug/ID | `window.scrollTo({ top: 0, behavior: 'instant' })` | 视口瞬时置顶，屏幕阅读器对齐 `#article-content` |
| **连续翻页** | PUSH | 点击上一篇 / 下一篇 | `window.scrollTo({ top: 0, behavior: 'smooth' })` | 视觉平滑置顶，进度条重置 |
| **返回历史列表** | POP / 定向 LINK | 点击顶部返回或浏览器后退 | **恢复历史位置 (Restore Scroll)** | 等待列表数据进入 `ready` 状态后，精准滚动回 `scrollY` |

#### 2.3.2 滚动恢复实现规范
- 废弃当前无脑 `window.scrollTo(0, 0)` 的全局 `useScrollToTop` 行为。
- 在列表页面（`PostsPage`, `SearchPage`, `NotesPage`）建立滚动高度登记与恢复器：
  1. **离场记录**：在文章卡片点击事件触发瞬间，通过 `window.scrollY` 将即时数值写入 `rootSource.scrollY`。
  2. **进场恢复**：
     - 当列表页面检测到带有 `restoreScroll: true` 且包含有效 `scrollY` 时；
     - 必须在数据加载完成（`state === 'ready'` 且 DOM 节点挂载完毕）后的 `requestAnimationFrame` 中调用：
       ```typescript
       window.scrollTo({
         top: targetScrollY,
         behavior: 'instant', // 恢复避免冗长平滑滚动造成眩晕
       });
       ```
     - 辅以 `targetCard.scrollIntoView({ block: 'nearest' })` 兜底，防止因图片懒加载造成的微小高度抖动。

### 3.2 状态流转 Tabs 与统计徽章规范

#### 3.2.1 页签定义与状态流转

后台文章列表必须提供 4 个标准状态页签，顶部横向排列：

```
[ 全部 (24) ]   [ 草稿 (3) ]   [ 已发布 (18) ]   [ 已归档 (3) ]
```

1. **全部 (`all`)**：显示所有未被物理删除的文章（包含草稿、已发布、已归档），默认排序列出。
2. **草稿 (`draft`)**：仅显示本地保存、尚未发布至对外阅读界面的创作中文章。
3. **已发布 (`published`)**：已生成正式发布快照、对外提供阅读的文章。
4. **已归档 (`archived`)**：软删除/历史封存文章。此页签下操作按钮变为【恢复为草稿】。

#### 3.2.2 动态统计徽章 (Stats Badges)
- 每个页签后附带圆角胶囊徽章（Badge），显示该状态下的真实数字。
- 当处于该页签时，徽章呈反色高亮；数据加载中时呈现轻量骨架闪烁。

### 3.3 综合筛选与排序控制条规范

#### 3.3.1 控制条布局 (Grid/Flex)
位于状态 Tabs 下方，自左至右包含：
1. **全文检索输入框**：
   - 宽度：自适应（min-width: 240px）。
   - 内置清除按钮（`×`），300ms 自动防抖。
   - 搜索范围：标题、摘要、正文字符。
2. **分类下拉筛选框 (Category Dropdown)**：
   - 动态汇聚知识库已有分类（如：全部分类、系统设计、前端架构、网络协议）。
3. **标记过滤开关 (Filter Toggles)**：
   - `[ ] 仅看置顶`
   - `[ ] 仅看精选`
4. **排序下拉选择器 (Sort Select)**：
   - `最近更新时间 (降序 - 默认)` (`updated_desc`)
   - `发布时间 (降序)` (`published_desc`)
   - `标题字典序 (升序)` (`title_asc`)

### 3.4 URL 参数全量双向绑定机制 (LIST-01)

#### 3.4.1 URL Search Params 映射规则
列表所有的状态切换必须无条件实时体现在浏览器 URL 地址栏中：

| UI 控件状态 | URL 查询参数 | 缺省值 (缺省时自动清理 URL) | 示例 |
| :--- | :--- | :--- | :--- |
| 状态页签 | `tab` | `all` | `?tab=draft` |
| 搜索关键词 | `q` | 空字符串 `""` | `?q=react` |
| 分类筛选 | `category` | 空字符串 `""` | `?category=Engineering` |
| 仅看置顶 | `pinned` | `false` | `?pinned=true` |
| 仅看精选 | `featured` | `false` | `?featured=true` |
| 排序方式 | `sort` | `updated_desc` | `?sort=published_desc` |
| 当前页码 | `page` | `1` *(大于 1 时显示)* | `?page=2` |

#### 3.4.2 路由同步与历史动作规则
- **交互动作驱动 URL**：
  - 更改 Tab、Category、Sort、Pinned、Featured 时，重置 `page = 1`，使用 `setSearchParams(next, { replace: true })`，避免产生过量无用历史记录。
  - 更改 Page（翻页）时，使用 `setSearchParams(next, { replace: false })`（PUSH），允许用户点击浏览器后退按钮返回上一页。
- **URL 驱动 UI 初始化**：
  - 页面初次加载或监听到 `popstate`（浏览器前进/后退）时，直接解析当前 URL 参数赋给内部状态并拉取对应数据。刷新页面后 100% 保持原有筛选与页码。

### 3.5 桌面端数据表格 vs 移动端卡片视图规范

#### 3.5.1 桌面端 (≥1024px) 数据表格 (Table Layout)
彻底废弃原有直接把长标题、摘要和操作堆砌在一起的凌乱栅格，采用规范工程数据表格：

| 列名 | 宽度定义 | 内容元素及交互行为 |
| :--- | :--- | :--- |
| **选择** | 48px 固定 | 单选复选框 `<input type="checkbox">` |
| **文章标题与摘要** | 弹性 (min 320px) | - **大标题**：加粗高亮，鼠标悬浮下划线，**点击直接进入编辑工作台** (`/knowledge/notes/:id`)<br>- **摘要次行**：单行截断省略 (`text-overflow: ellipsis`)，浅灰字号<br>- **标签组**：紧凑 Tag 胶囊，点击快捷加入筛选 |
| **分类** | 120px 固定 | 分类徽章，点击可直接激活该分类筛选 |
| **状态/标记** | 140px 固定 | - 状态徽章：草稿 (黄)、已发布 (绿)、已归档 (灰)<br>- 图标标记：置顶 (📌)、精选 (⭐) |
| **更新时间** | 140px 固定 | 等宽时间字型 (`font-mono`)，如 `2026-10-01 14:20`，悬浮显示相对时间（如“3小时前”） |
| **操作** | 180px 右对齐 | **独立操作按钮组** (严禁拼接长文案)：<br>1. `[编辑]`：跳转编辑工作台<br>2. `[阅读]`：打开阅读视图<br>3. `[归档]` 或 `[恢复]`：次要危险动作，归档需气泡二次确认 |

#### 3.5.2 移动端 (<1024px) 结构化卡片视图 (Card Layout)
- 垂直卡片流排版，单卡片内分为三层：
  - **顶层**：分类标签 + 状态徽章 + 置顶/精选图标。
  - **中层**：大标题（点击进入编辑）+ 最多 2 行摘要截断。
  - **底层操作栏**：更新时间靠左；靠右横向排列 `[阅读]`、`[编辑]`、`[归档/恢复]` 独立按钮，按钮触控热区均 ≥44px。

### 3.6 批量管理操作与逐项反馈 (LIST-04)

#### 3.6.1 批量操作悬浮条 (Bulk Floating Bar)
- 当用户勾选至少 1 篇文章复选框时，表格顶部平滑滑出批量操作栏：
  - 左侧：`已选中 5 篇文章` | `[全选当前页]` | `[取消选择]`
  - 右侧行动组：
    - `[批量归档]` (若选区含未归档文章)
    - `[批量恢复]` (若选区含已归档文章)
    - `[批量调整分类]` (下拉菜单选择目标分类)

#### 3.6.2 逐项处理反馈与重试设计 (LIST-04 核心)
- 严禁假全成功。批量任务通过并行队列执行后，弹出清晰的结果报告对话框或顶部横幅：
  - **全部成功**：浮出绿色通知：`已成功批量归档 5 篇文章`，清空勾选。
  - **部分失败**：弹出警告框：
    > 批量操作完成：成功 3 项，失败 2 项。
    > - 失败项 1：《分布式共识推导》— 发生并发冲突，文档正在被另一进程编辑。
    > - 失败项 2：《网络协议底层探秘》— 鉴权超时。
  - **失败保留与重试**：
    - 列表中自动**保留失败项的勾选状态**，取消成功项的勾选。
    - 批量条保留【重试失败项】按钮，方便用户快速再次发起。

### 3.7 空状态双重区分与末项归档规范 (LIST-02, LIST-03)

#### 3.7.1 知识库暂无文章 vs 搜索筛选无结果
1. **全局空状态 (Global Empty State)**：
   - 触发：知识库数据库内没有任何文章记录。
   - 引导插图：书架/文档剪影。
   - 文案：“知识库暂无文章”。
   - 描述：“记录推导与实践，沉淀属于你的技术知识资产。”
   - 动作：【新建第一篇文章】、【导入 Markdown 文档】。
2. **检索无结果空状态 (Search/Filter Empty State)**：
   - 触发：存在文章，但在当前关键词 `q` 或分类 `category` 下无匹配项。
   - 引导插图：放大镜/筛选漏斗。
   - 文案：“未找到匹配的文章”。
   - 描述：“未找到与当前搜索词或筛选条件符合的文章。”
   - 动作：【一键清空筛选条件】（点击立即重置 `q`、`category`、`tab` 并刷新）。

#### 3.7.2 末项归档后的页码自动回退 (LIST-03)
- 场景：用户停留在第 3 页，且第 3 页仅有最后 1 篇文章。用户执行了“归档”操作。
- 规范：
  - 前端执行归档变更并完成数据刷新后，若检测到总页数缩减且当前 `page > totalPages`（即当前页码变为无数据空页）；
  - 系统必须**自动平滑将页码调整为 `page - 1`**（即回退到第 2 页）并重新请求数据；
  - 严禁停留在第 3 页向用户展示“暂无文章”的假空状态。

### 4.5 草稿自动保存与独立发布快照规范 (EDIT-02, PUB-01 ~ PUB-04)

#### 4.5.1 自动保存防抖与防并发覆盖机制 (EDIT-02)
- **触发机制**：用户每次敲击键盘修改标题、正文或属性，触发 1500ms ~ 2000ms 防抖计时器。
- **并发锁与时序防护**：
  - 维护 `editingRevisionId` 与 `persistedRevisionId`。
  - 当发出保存网络请求时，保存请求携带当前快照的 Revision 时间戳。
  - 若在网络延迟期间用户继续进行了键入，旧请求成功返回时，**绝不能以响应数据覆盖本地正在输入的新内容**。
  - 仅当服务器确认当前草稿写入成功且本地无更新修改时，状态才转为 `saved`。

#### 4.5.2 独立发布快照与状态流转机理 (PUB-01 ~ PUB-04)

```
       [新建草稿]
           │
           ▼
     ┌───────────┐       明确点击【发布文章】        ┌─────────────┐
     │   草稿    │ ─────────────────────────────> │   已发布    │
     │  (Draft)  │ <───────────────────────────── │ (Published) │
     └───────────┘       点击【撤回为草稿】          └─────────────┘
           │                                             │
           │ 归档                                        │ 归档
           ▼                                             ▼
     ┌─────────────────────────────────────────────────────────┐
     │                      已归档 (Archived)                  │
     └─────────────────────────────────────────────────────────┘
                                   │
                                   │ 恢复操作 (强制恢复为草稿)
                                   ▼
                             ┌───────────┐
                             │   草稿    │
                             └───────────┘
```

1. **草稿改动不污染发布快照 (PUB-01)**：
   - 已发布文章在编辑工作台被修改后，自动保存仅更新后台草稿记录。
   - **前台阅读视图与接口读取严格基于 `published_snapshot`**。在作者明确点击【更新发布】之前，读者看到的依然是上一次稳定发布的版本。
2. **明确更新发布 (PUB-02)**：
   - 点击【更新发布】后，系统在 D1 事务中将当前草稿原子覆写至发布快照字段，更新 `published_at` 时间戳并刷新全站内容缓存。
3. **撤回发布安全 (PUB-03)**：
   - 文章撤回为草稿后，私有阅读接口立即返回 404 或无权访问，严格清理缓存，避免已撤回内容泄露。
4. **恢复归档文章限制 (PUB-04)**：
   - 归档文章恢复时，**只能恢复为草稿状态 (`status = 'draft'`)**，严禁直接自动重新发布上线。

## 5. 交互安全与异常反馈规范

### 5.1 未保存离开拦截机制 (EDIT-01)

#### 5.1.1 脏数据判断与双层防御
- **脏数据定义**：`isDirty = JSON.stringify(currentDraft) !== JSON.stringify(lastPersistedDraft)`。
- **第一层：原生浏览器关闭/刷新拦截**：
  - 当 `isDirty === true` 时，注册 `window.addEventListener('beforeunload', handleBeforeUnload)`。
  - 触发时调用 `event.preventDefault()`，浏览器将弹出原生“您所做的更改可能无法保存”提示。
- **第二层：SPA 站内路由离开拦截 (React Router)**：
  - 使用导航守卫（如 `useBlocker`）监听任何站内跳转（如点击侧边栏“概览”、点击顶部面包屑、浏览器点击后退）。
  - 若 `isDirty === true`，阻断当前跳转，屏幕中央弹出系统级模态对话框：
    - **标题**：“当前有未保存的修改”
    - **正文**：“您在文章《{title || '未命名草稿'}》中的编辑尚未保存。现在离开，最新修改将会丢失。”
    - **行动按钮**：
      - `[放弃修改并离开]`：危险按钮，清空脏状态并放行跳转。
      - `[保存草稿并离开]`：立即执行异步持久化，成功后自动放行跳转。
      - `[留在当前页面]`：主行动按钮，关闭弹窗，光标聚焦回编辑区。

### 5.2 历史版本恢复安全熔断机制 (VER-01, VER-02)

#### 5.2.1 现有风险分析与熔断原则
现有代码在恢复历史版本时，`try { autosave(); createVersion(); } catch { // continue }` 忽略了备份失败，一旦网络抖动导致当前快照创建失败，直接恢复旧版本将会**永久冲刷掉用户当前辛苦撰写的最新内容**。

#### 5.2.2 严格熔断时序事务流 (VER-01)

```
[用户点击“恢复此版本”]
         │
         ▼
[弹出模态对话框：确认是否恢复？]
         │ 用户点击【确认恢复】
         ▼
[步骤 1: 强制保存当前草稿] ──── 失败 ───> [🛑 熔断中止！弹出错误，禁止覆盖正文]
         │ 成功
         ▼
[步骤 2: 为当前工作区创建安全保护快照] ──── 失败 ───> [🛑 熔断中止！弹出错误，禁止覆盖正文]
         │ 成功
         ▼
[步骤 3: 仅在前两步均成功后，载入旧版本至 Tiptap 画布并保存]
         │
         ▼
[步骤 4: 浮出成功通知 Toast：“已成功恢复旧版本，原编辑内容已备份至版本历史”]
```

1. **强前置条件**：步骤 1 和步骤 2 中任何网络异常、服务端 500、鉴权失效，整个恢复事务必须立即中止，弹窗保持开启并提示：
   > “安全保护失败：无法为当前正在编辑的内容创建安全备份快照。为防止您的工作丢失，系统已终止恢复。请检查网络后重试。”
2. **版本记录纯洁性 (VER-02)**：
   - 自动保存绝不制造多余的手动快照版本，只有显式点击【保存快照】或【恢复旧版本前的保护动作】才计入手动版本历史。

### 5.3 资源与版本加载失败的真实反馈规范 (ASSET-01, IMP-01)

#### 5.3.1 禁止将错误伪装为空列表
- 当 `listKnowledgeAssets` 或 `listKnowledgeNoteVersions` 接口返回 5xx、403 或网络失败时：
  - **严禁**展示“暂无附件”或“暂无历史版本”！
  - **必须**在对应面板内展示明确的错误状态卡片：
    - 带有警告图标 `⚠`；
    - 明确错误文案：“附件列表加载失败 (网络连接超时)”；
    - 提供【重新加载】按钮，点击单独重试该模块接口。

#### 5.3.2 附件上传/下载单项错误隔离 (ASSET-01)
- 某个附件上传因大小超限 (15MB) 或格式不合规失败时，仅在该文件行展示红色错误提示与“重试”/“移除”操作，**严禁清空或重置其他已就绪的附件**，正文编辑画布保持正常输入。

#### 5.3.3 Markdown 导入单项失败与重试 (IMP-01)
- 批量导入 10 个 Markdown 文件时，若其中 2 个文件格式损坏或 Slug 冲突：
  - 其余 8 个成功文件必须正常写入数据库；
  - 导入结果界面清晰列出：“成功 8 篇，失败 2 篇”；
  - 针对失败的 2 篇显示具体原因（如“YAML frontmatter 解析失败”），并提供【仅重试失败项】按钮，避免重复导入成功项造成重复数据。

### 6.2 键盘导航与无障碍 (a11y) 规范 (UI-02)

#### 6.2.1 焦点移动与跳过链接 (Skip Links)
- 全站最顶端提供跳过导航链接：`<a className="skip-link" href="#main-content">跳到主要内容</a>`。按 `Tab` 键首先唤起，回车直接聚焦主工作区。
- **页面推进与返回**：从列表进入详情页后，焦点直接对齐文章大标题；点击返回按钮后，焦点精准回到原列表中的触发卡片上。

#### 6.2.2 模态对话框与抽屉的焦点陷阱 (Focus Trap)
- 任何对话框（如未保存离开警告、删除附件确认、版本恢复确认）或移动端抽屉打开时：
  1. 页面滚动锁定 (`body { overflow: hidden }`)。
  2. 记录当前激活的元素 `restoreFocusRef.current = document.activeElement`。
  3. 焦点强制移入对话框内的【取消】或主行动按钮。
  4. 启用焦点陷阱：按 `Tab` 或 `Shift+Tab` 只能在对话框内的可交互元素之间循环，绝不允许焦点穿透到底层页面。
  5. 按键盘 `Escape` 键，立即关闭对话框，焦点平滑交还给原触发元素。

#### 6.2.3 编辑器快捷键支持
- `Ctrl/Cmd + S`：立即保存草稿并阻断浏览器默认网页保存行为。
- `Ctrl/Cmd + Shift + P`：快速呼出文章预览。
- `Ctrl/Cmd + B` / `Ctrl/Cmd + I` / ``Ctrl/Cmd + ` ``：文本格式切换。
- `Escape`：在编辑器内弹出菜单或气泡时，按 Esc 优先关闭气泡。

#### 6.2.4 ARIA 语义与动态通知
- 保存状态指示器：必须标记 `role="status" aria-live="polite"`。
- 致命错误/保存失败警告：标记 `role="alert" aria-live="assertive"`。
- 状态页签组：使用 `role="tablist"`，各项标记 `role="tab"` 与 `aria-selected="true|false"`。
